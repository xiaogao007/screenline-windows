# 从 Tendedero 到 Screenline

截图晾台（Screenline）以 [Tendedero](https://github.com/alejandrobujan/tendedero) 的“截图悬挂在屏幕顶端，随取随用”交互为灵感，使用 C#、WPF 和 Windows API 重新实现。它不是直接运行原来的 Swift/macOS 程序。构建与使用说明见项目根目录的 README。

本次参考的上游版本：`2c3ffd95f173585260aa198e85d3ea62a878f688`。

## 平台适配

| 原项目行为 | 本版本处理方式 |
| --- | --- |
| AppKit / SwiftUI 窗口与菜单栏图标 | WPF 顶边悬浮晾台、Windows 通知区域图标、全局快捷键。 |
| macOS 原生截图由原系统快捷键完成，应用只监控新文件 | 增加自己的区域截图窗口；截图目录监控作为另一种图片入口。 |
| macOS Markup 编辑原文件 | 内置画笔标注窗口；保存为一张新图片，保留原图。 |
| Preview / Quick Look | 内置图片预览与标注窗口。 |
| 原图始终留在原路径，只有收件箱内文件会被应用清理 | 导入时复制到本地管理库；应用操作自己的副本，外部原文件保留。 |
| 自有收件箱的移除、清空及容量溢出会移到系统废纸篓 | 移除和清空写入应用自己的持久化移除记录，支持撤销；图片文件仍保留在管理库。 |
| 拖到应用复制，拖到文件夹移动并离开晾台 | 拖出始终请求复制，保留晾台中的副本；也可以使用“另存图片”。 |
| 可选的剪贴板图片监听 | 默认关闭，在设置中手动开启；跳过文本、文件和支持的隐私标记，自身复制不会再次收集。 |
| 自动隐藏与全屏场景 | 顶边悬停展开，指针离开后收起；全屏抑制使用 Windows 前台窗口边界判断。快捷键可以主动展开。 |
| macOS 图标与应用名 | 使用独立的 Screenline / 截图晾台名称与图形。 |

## 文件与数据

当前图片入口支持 PNG、JPG/JPEG、BMP 和 GIF。GIF 作为静态图片使用。每个文件最多 100 MB，图片总像素最多一亿；缩略图按需解码，原始导入副本保留。重复导入以文件内容的 SHA-256 去重。

本地数据目录为 `%LOCALAPPDATA%\Screenline`。索引与设置使用 JSON，并在替换时保留备份。重新启动会读取现有索引。图片路径不可读时保留记录，避免悄悄删除数据。

移除、清空以及撤销操作针对晾台列表。它们不会永久删除图片，也不会清空 Windows 回收站。管理库会持续占用磁盘空间；需要清理历史副本时，先退出应用并备份数据目录。

## 与上游尚未对齐的功能

- 不修改 Windows 截图工具、Win + Shift + S、Win + PrtSc 的系统保存设置。
- 不提供 macOS Force Touch 压力手势。
- 不处理录屏 MOV/MP4、视频缩略图与视频裁剪。
- 未实现上游全部 HEIC、TIFF、WebP 图片格式。
- 未复刻上游全部语言、尺寸/容量选项、声音与动画细节。
- 文件拖出采用复制语义，未实现原项目的拖到系统废纸篓删除语义。目标程序是否接受图片或文件取决于它自身的拖放支持。
- 当前采用系统 DPI 感知。多显示器使用不同缩放比例时，需在实际设备上检查截图选区与晾台位置。
